# 系统优化方案

## 参考项目分析（douyin_huohua）

参考项目是一个成熟的抖音续火花商业化系统，具有完整的数据库架构和商业功能。

### 核心架构特点

1. **完整的用户体系**
   - 管理员表（admins）
   - 用户表（users）带余额、代理等级
   - 用户套餐关系表（user_packages）
   - 订单系统（orders）
   - 卡密系统（card_keys）
   - 代理等级配置（agent_levels）

2. **抖音账号管理**
   - 支持多账号管理（douyin_accounts）
   - Cookie状态追踪和过期管理
   - 默认账号机制
   - 二维码登录记录（douyin_qrcodes）

3. **任务系统**
   - 定时任务表（scheduled_tasks）
   - 任务执行记录（douyin_tasks）
   - 支持Cron和间隔执行两种模式
   - AI消息生成支持
   - 任务执行统计

4. **日志与审计**
   - 用户日志表（user_logs）
   - 详细的操作记录和变更追踪

5. **系统配置**
   - 灵活的配置表（system_configs）
   - 分组管理（basic/email/system/payment/ai）
   - 公告系统（announcements）

## 当前项目状态分析

### 优点
- ✅ 核心功能完整（登录、发送消息、定时任务）
- ✅ 使用文件持久化（state_store.py）
- ✅ 纯逻辑分离（spark_core.py）
- ✅ 前后端分离架构（Vue3 + FastAPI）
- ✅ 错误分级和重试机制
- ✅ 消息通知功能（邮件/推送）

### 需要优化的地方

#### 1. 数据持久化（高优先级）
**问题：** 当前使用JSON文件存储，缺乏：
- 数据关系管理
- 并发事务支持
- 复杂查询能力
- 数据完整性约束

**优化方案：** 引入数据库层（SQLite起步，支持MySQL/PostgreSQL）

#### 2. 多账号支持（高优先级）
**问题：** 当前仅支持单个抖音账号

**优化方案：**
- 账号管理页面
- 账号切换机制
- Cookie状态管理
- 默认账号设置

#### 3. 用户系统增强（中优先级）
**问题：** 当前只有简单的管理员登录

**优化方案：**
- 多管理员支持
- 用户角色权限
- 登录日志
- 会话管理优化

#### 4. 任务管理增强（中优先级）
**问题：** 任务配置较简单，缺乏执行历史

**优化方案：**
- 任务执行历史记录
- 任务分组和标签
- 批量操作
- 任务统计分析

#### 5. AI消息生成（中优先级）
**问题：** 当前使用固定消息池

**优化方案：**
- 集成AI API（OpenAI/国内大模型）
- 自定义提示词
- 消息风格配置
- 上下文记忆

#### 6. 系统配置管理（低优先级）
**问题：** 配置分散在代码和环境变量

**优化方案：**
- 统一配置界面
- 配置分组管理
- 配置验证
- 配置导入导出

#### 7. 好友管理增强（低优先级）
**问题：** 好友列表无持久化，无备注功能

**优化方案：**
- 好友信息持久化
- 自定义备注
- 好友分组
- 发送历史查询

#### 8. 日志系统（低优先级）
**问题：** 日志功能基础

**优化方案：**
- 操作日志详细记录
- 日志分级过滤
- 日志导出
- 日志统计分析

## 技术栈建议

### 数据库
- **开发/小规模部署：** SQLite（零配置）
- **生产环境：** MySQL 8.0+ 或 PostgreSQL 13+

### ORM选择
- **SQLAlchemy 2.0+**（成熟、功能强大）
- 或 **Tortoise ORM**（异步友好，轻量）

### 迁移工具
- **Alembic**（SQLAlchemy配套）

### 缓存（可选）
- **Redis**（会话、限流、任务队列）
